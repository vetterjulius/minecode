# B2B SaaS Reference Application

This application represents a fully end-to-end generated B2B SaaS system, composed deterministically using Minecode from its declarative description in `app.yaml`.

## Features Included

1.  **Authentication:** Fully functional Supabase auth routing handlers, user password authentication, mock password reset, and session control.
2.  **Multi-Tenant Organizations:** Workspaces/organizations tenant structures, user memberships, and email join invitations.
3.  **Role-Based Access Control (RBAC):** Roles, permissions, and roles listing endpoint.
4.  **Billing:** Stripe integration mappings (customers, subscriptions) and checkout/webhook API handlers.
5.  **Database Primitive:** Direct SQL DDL schemas and structured database migrations.

## Project Structure

This reference app shows the outputs generated by the `@minecode/nextjs-supabase` adapter from the `app.yaml` blueprint. According to the Minecode architecture, a stack adapter produces virtual files that are organized into key directories under the target project directory.

These directories are:

- `app/`: Next.js App Router source files (including backend API route handlers under `app/api/api/` and routes for login, rbac-admin, organizations and billing settings pages).
- `generated/`: Built-in central directory for compiled artifact declarations (such as type definitions in `generated/types/database.ts`). Manual edits in this directory are overwritten on the next compile.
- `config/`: Configuration files and mappings (e.g. `config/permissions.ts` generated from security contracts).
- `supabase/migrations/`: Structured PostgreSQL DDL migration scripts corresponding to entity definition tables and builtin feature migration SQL scripts.

## How to Initialize, Run & Deploy

Because Minecode compiles declarative features into structured code files inside a target project skeleton rather than outputting a fully bundled application with pre-packaged build infrastructure and config lockfiles, some manual setup is required to run the generated code as a Next.js application.

### 1. Initialize a Standard Next.js Skeleton Project

First, create a standard Next.js workspace at your desired target directory (for example, in a separate directory or by copy-pasting the compiled files there):

```bash
# Create a standard Next.js application with TypeScript and Tailwind
npx create-next-app@latest my-b2b-saas-app --typescript --tailwind --app --src-dir=false --eslint
cd my-b2b-saas-app
```

### 2. Install Required Stack Dependencies

Add the Supabase auth helper and standard client libraries to the project dependencies:

```bash
npm install @supabase/supabase-js @supabase/auth-helpers-nextjs
```

### 3. Copy Generated Reference Files

Overlay the files compiled by Minecode (`app/`, `generated/`, `config/`, and `supabase/` generated folders) onto the root of your standard Next.js project directory, replacing the default placeholder files.

### 4. Setup Local PostgreSQL or Supabase Database

To run database migrations:

```bash
# Initialize Supabase configuration locally
supabase init

# Apply the generated database migrations inside 'supabase/migrations/' (including subdirectories)
# or paste them into your Supabase SQL editor console.
```

### 5. Configure Environmental Variables

Add a `.env.local` file at the root of the project with your database key configurations:

```env
NEXT_PUBLIC_SUPABASE_URL=your_supabase_project_url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_supabase_anon_key
```

### 6. Run the Next.js Dev Server

```bash
npm run dev
```

Open `http://localhost:3000` to interact with your fully composed Next.js B2B SaaS application.
